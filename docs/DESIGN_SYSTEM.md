## 1. Design Principles
[confirmed from codebase]

- **Pink-forward palette**: "Rose Bloom" theme uses a vivid rose primary (hsl(345 82% 52%)) with violet accent (hsl(280 60% 50%))
- **Generous whitespace**: Consistent spacing scale with gap-1.5 (6px) as base unit for form fields
- **Soft, rounded surfaces**: Border radius scale from 4px to 24px, with 12px (rounded-xl) as default for buttons and cards
- **Subtle elevation**: Shadow system from shadow-xs to shadow-xl, with focus rings using ring-2
- **Flat surfaces, no gradients** (except skeleton shimmer animation)
- **Semantic color usage**: success/warning/destructive colors for status states only
- **Mobile-first responsive**: Max-width container at 2rem (512px) for main content, with bottom tab bar navigation

## 11. Anti-patterns (Do Not Do)
[confirmed from audit findings]

1. **Do not use hardcoded slate colors**: Never use `bg-slate-*`, `text-slate-*`, `border-slate-*`. Use design tokens instead (`bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`).
2. **Do not use hardcoded white backgrounds**: Never use `bg-white`. Use `bg-card` or `bg-background` instead.
3. **Do not use hardcoded semantic colors**: Never use `text-rose-600`, `text-emerald-600`, `text-amber-600`. Use `text-destructive`, `text-success`, `text-warning` instead.
4. **Do not use inline styles**: Avoid inline styles in JSX. Use Tailwind classes or CSS variables.
5. **Do not skip the cn() utility**: Always use the `cn()` utility from `@/lib/utils` for conditional class merging.
6. **Do not use arbitrary values without reason**: Avoid arbitrary values like `h-[123px]` unless absolutely necessary. Use the spacing scale.
7. **Do not mix color systems**: Don't mix HSL, hex, and Tailwind color names. Stick to CSS custom properties.
8. **Do not use hardcoded border-radius**: Don't use `rounded-[12px]`. Use `rounded-xl`, `rounded-2xl`, etc.
9. **Do not use hardcoded shadows**: Don't use `shadow-[0_4px_6px_-1px_rgba(0,0,0,0.1)]`. Use `shadow-sm`, `shadow-md`, etc.
10. **Do not use hardcoded z-index**: Don't use `z-[999]`. Use the z-index scale (z-40, z-50, z-[70]).
11. **Do not skip accessibility props**: Always include `aria-label`, `role`, `aria-invalid`, etc. where appropriate.
12. **Do not use magic numbers in forms**: Use the `INPUT_CLASS_NAME` constant from `app/onboarding/_lib/constants.ts` for consistent input styling.

## 12. Audit Findings & Recommendations
[confirmed from audit findings]

### Critical Inconsistencies

1. **Hardcoded slate colors in app routes** (80+ files affected)
   - Files: `app/page.tsx`, `app/categories/_components/create-category-form.tsx`, and 78+ others
   - Issue: Using `bg-slate-50`, `text-slate-500`, `text-slate-900`, `text-slate-600`, `text-slate-700`, `bg-slate-900`, `border-slate-300`
   - Recommendation: Replace with `bg-background`, `text-muted-foreground`, `text-foreground`, `border-border`

2. **Hardcoded white backgrounds**
   - Files: `components/ui/input.tsx`, `components/ui/select.tsx`, `app/categories/_components/create-category-form.tsx`
   - Issue: Using `bg-white` instead of `bg-card` or `bg-background`
   - Recommendation: Replace with `bg-card` for card surfaces, `bg-background` for general backgrounds

3. **Hardcoded semantic colors in components**
   - File: `components/ui/form-status.tsx`
   - Issue: Using `text-rose-600` and `text-emerald-600` instead of `text-destructive` and `text-success`
   - Recommendation: Replace with `text-destructive` and `text-success`

4. **Hardcoded slate colors in UI components**
   - File: `components/ui/rhf-fields.tsx`
   - Issue: Using `border-slate-200`, `text-slate-500`
   - Recommendation: Replace with `border-border`, `text-muted-foreground`

5. **Hardcoded background in loading container**
   - File: `components/ui/loading-container.tsx`
   - Issue: Using `bg-slate-50` for full-page variant
   - Recommendation: Replace with `bg-background`

6. **Inline styles in global error page**
   - File: `app/global-error.tsx`
   - Issue: Using inline styles with hardcoded HSL values
   - Recommendation: Convert to Tailwind classes using design tokens

### Gaps

1. **No defined spacing token scale**: Spacing values are scattered across components. Recommend creating a spacing scale in `globals.css` (e.g., `--space-1: 0.25rem`, `--space-2: 0.5rem`, etc.)

2. **No defined shadow token scale**: Shadow values are Tailwind defaults. Recommend documenting the shadow scale in CSS variables.

3. **No defined z-index token scale**: Z-index values are scattered. Recommend documenting the z-index scale in CSS variables.

4. **No defined typography scale**: Typography sizes are scattered. Recommend documenting the typography scale in CSS variables.

5. **No defined animation token scale**: Animation durations are scattered. Recommend documenting the animation scale in CSS variables.

### Recommendations

1. **Create a migration plan** to replace all hardcoded `bg-slate-*`, `text-slate-*`, `bg-white` values with design tokens across the 80+ affected files.

2. **Add linting rules** to prevent hardcoded color values (e.g., using eslint-plugin-tailwindcss).

3. **Create a shared input class constant** similar to `INPUT_CLASS_NAME` in `app/onboarding/_lib/constants.ts` and use it across all forms.

4. **Document the design tokens** in a separate `tokens.css` file for easier reference.

5. **Create component storybook** or visual documentation to ensure consistency.

6. **Add automated visual regression testing** to catch design inconsistencies.

7. **Standardize the onboarding input class**: The `INPUT_CLASS_NAME` constant in `app/onboarding/_lib/constants.ts` is a good pattern. Consider moving it to a shared location and using it across all forms.

8. **Fix form-status.tsx**: Replace `text-rose-600` with `text-destructive` and `text-emerald-600` with `text-success`.

9. **Fix rhf-fields.tsx**: Replace `border-slate-200` with `border-border` and `text-slate-500` with `text-muted-foreground`.

10. **Fix loading-container.tsx**: Replace `bg-slate-50` with `bg-background`.
