# Priority Matrix

## P0 - Required Before Redevelopment

| Item | Why |
|---|---|
| Unified financial confirmation model | Prevents unsafe or unclear money actions. |
| Journey receipts | Makes multi-domain changes trustworthy. |
| State-labeled amounts | Prevents confusion between cash, plan, expected, estimated, due, realized, unrealized. |
| Fast daily money capture | Core recurring behavior must be efficient. |
| Health read-only enforcement | Preserves BR-24 and user trust. |
| Investment not-cash/advice guardrails | Prevents high-risk misunderstanding. |
| Inbox owner/return behavior | Prevents navigation and ownership confusion. |
| Accessible confirmation dialogs | Ensures consequential actions are understandable by all users. |

## P1 - Required During Redevelopment

| Item | Why |
|---|---|
| Required-first progressive forms | Reduces mobile cognitive load. |
| Origin-aware cross-module continuity | Keeps users oriented. |
| Owner-specific empty/recovery states | Helps first-time users proceed safely. |
| Mobile sticky action behavior | Makes long flows usable one-handed. |
| Money Products grouping behavior | Keeps cards/loans/savings/investments predictable. |
| Together policy staging | Avoids abstract early decisions. |

## P2 - Polish

| Item | Why |
|---|---|
| Microcopy refinement | Improves confidence after core clarity exists. |
| Completion motion | Adds delight without changing behavior. |
| Advanced search/filter polish | Improves efficiency for high-volume users. |
