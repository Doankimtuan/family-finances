# Friction Analysis

## Main Recommendations

| Recommendation | Current issue | User impact | Proposed UX behavior | Affected screens | Priority |
|---|---|---|---|---|---|
| Day-0 Home essentials | First-time Home can expose too many concepts. | New users hesitate. | Show add account, starter plan, invite partner first. | Home, Onboard | P0 |
| Fast capture | Capture can be slowed by category/perfection pressure. | Daily use suffers. | Required fields first, defaults, optional note/category recovery. | Transactions | P0 |
| Money Products grouping | Cards/Loans/Savings/Investments can compete. | Users do not know where to go. | Group as Money Products with concise next action per product. | Money | P1 |
| Financial receipts | Actions can feel magical. | Trust drops. | Show real money/plan/decision outcome after confirmation. | Money, Plan, Inbox | P0 |
| Consequence previews | Users may not see fee/penalty/interest/source. | Unsafe confirmation. | Preview before consequential financial actions. | Loans, Savings, Cards, Investments | P0 |
| Investment clarity | Estimated value can look spendable. | Financial misunderstanding. | Always label estimated/unrealized/not cash/date/source. | Investments, Health | P0 |
| Health source links | Insights can feel like judgment. | Anxiety and confusion. | Explain contributing factors and link to source. | Health | P1 |
| Origin-aware back | Cross-module flow loses context. | Disorientation. | Preserve origin and list state. | Inbox, Health, Home, Account detail | P1 |
| Settings staging | Policies too early are abstract. | Blind setup choices. | Safe defaults; introduce when relevant. | Onboard, Together | P1 |
| Accessibility labels | Amount cards can be terse. | Assistive tech ambiguity. | Add meaning to accessible amount/date labels. | All money screens | P0 |
