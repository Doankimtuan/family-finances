# Rejected Features

## Permanently Rejected Capabilities

No Phase 1 or Phase 2 Goals capability is permanently rejected at this decision point.

## Board Rationale

The discovered capabilities are either:

- Simple and validated enough to approve.
- Valuable but requiring strict modification.
- Realistic but too complex or risky for the current product stage.

No discovered capability directly requires permanent rejection because advisory-grade, tax-aware, investment-return, and autonomous financial planning were already outside the Goals discovery scope.

## Rejection Guardrails

Future Goals proposals should be rejected if they:

- Treat goal progress as a bank, cash, wallet, investment, or savings product balance.
- Let Goals mutate Accounts, Transactions, Cards, Loans, Savings, or Health.
- Provide advisory-grade financial recommendations.
- Hide uncertainty about source evidence.
- Add automation that users cannot understand.
- Create partner surveillance or blame dynamics.
