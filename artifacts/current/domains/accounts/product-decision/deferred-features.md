# Deferred Features

| ID | Capability | Reason | Conditions to reconsider | Suggested future phase |
|----|------------|--------|--------------------------|------------------------|
| ACC-PD-014 | Account number mask | Useful but raises privacy/setup questions. | User research shows account labels alone are insufficient. | Version 1.x |
| ACC-PD-015 | Per-account currency | Not common enough for Vietnam-first MVP; exchange-rate risk. | Multi-currency need validated by target households. | Version 2.x |
| ACC-PD-018 | Balance history snapshots | Analytical value, not core account comprehension. | Users ask for historical balance trends after core usage stabilizes. | Version 2.x |
| ACC-PD-019 | Imported bank/wallet balances | High provider reliability and consent risk. | Vietnam integration feasibility and user trust validated. | Version 2.x |
| ACC-PD-021 | Account grouping | Useful only once account count grows. | Users regularly maintain many accounts. | Version 1.x |
| ACC-PD-023 | Statement attachment/reference | Adds document-management burden. | Reconciliation research shows statement references are common need. | Version 2.x |
| ACC-PD-025 | Multi-currency account support | Same complexity as per-account currency, broader scope. | Travel, remote income, remittance, or study-abroad usage becomes common. | Version 2.x |
| ACC-PD-026 | Open-banking/provider feed integration | Premature and risky without stable provider ecosystem. | Legal/provider access, consent, reliability, and duplicate handling validated. | Version 2.x |
| ACC-PD-027 | Precise liquidity classification | Simple liquidity is enough now. | Emergency and term-product usage shows simple labels are insufficient. | Version 2.x |
| ACC-PD-028 | Account sub-classification | Low current value; existing board already deferred. | Specific business behavior depends on subtypes. | Future |
| ACC-PD-029 | Cross-border wallet/QR awareness | Future pressure, not current core behavior. | Cross-border QR becomes common for target households. | Future |
| ACC-PD-030 | Read-only investment/wealth accounts | Wealth is future scope and advisory risk exists. | Wealth domain is formally approved and bounded. | Future |
| ACC-PD-031 | Account access status | Provider-specific states premature. | Wallet/provider restrictions become frequent user issue. | Version 2.x |
| ACC-PD-032 | Stronger reconciliation workflow | Full workflow is too much before basic trust is proven. | Reconciliation becomes repeated pain in usage research. | Version 2.x |
| ACC-PD-033 | Provider connection status | Depends on provider feeds. | Provider-feed integration approved. | Version 2.x |
| ACC-PD-034 | Multiple balance concepts | Correct but too complex for current users. | Users demonstrate need to distinguish recorded/institution/available/pending. | Version 2.x |
| ACC-PD-036 | Fraud/dispute status awareness | Important but edge-case heavy. | Scam/dispute cases become frequent and domain boundaries are validated. | Future |
