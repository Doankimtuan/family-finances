# Loans UI-Surface Inventory and Discovery Report

**Scope:** Discovery only. No Loans redesign, route change, business-logic change, calculation change, Supabase/RPC change, styling update, or i18n modification was made.

**Repository:** `family-finances`

**Language mode:** English source and English live-route checks only. Vietnamese UI was not manually validated, and the existing i18n structure remains untouched.

## Executive summary

The current Loans experience is a schedule-driven Money child flow with one list page, one create sheet, one detail page, one nested full-schedule page, three detail action sheets, one inline archive-confirmation state, embedded payment history, embedded rate history, and a query-parameter-driven detail tab/year filter. The executable repayment path is **scheduled payment only**. Early payoff is estimate-only, and loan creation is explicitly tracking-only: it does not move borrowed cash into an account.

The primary active flow is:

> **Money hub → Loans list → Add loan sheet → Loan detail → Overview / Repayment schedule / History & actions → Pay this period → Review → Receipt; or Edit loan / Update future rate / Estimate early payoff / Archive loan.**

The most important future redesign risks are the distinction between **remaining principal** and **cash movement**, the schedule-derived payment behavior, the conditional floating/promotional interest branches, the former-member/read-only capability model, and the fact that “Close loan” archives a record rather than settling it. The current UI also has several design-system inconsistencies: static remaining principal is rendered with debt semantic color, some forms use native labeled controls rather than canonical shared controls, detail-not-found uses `EmptyState` instead of the canonical danger alert pattern, and legacy Cards/EMI compatibility names remain in active code.

The codebase search found **11 active files** under the Loans route subtree. The active route tree contains no separate disbursement flow, no separate source/destination-account page, no standalone payment-history page, no executable early-payoff flow, no delete action, no standalone confirmation dialog, and no mobile-only Loans route.

## Discovery and verification note

The repository was inspected from the attached `family-finances` working tree, including the canonical design-system guidance, Money hub, active Loans routes, application commands and queries, translations, tests, route helpers, and completed Debt discovery patterns. The attached computer’s Next development server responded to `GET /en/money/loans` with HTTP 200, but its returned HTML fallback contained the application “Page not found” state. The sandbox browser could not connect to the attached computer’s localhost, so this report makes no visual claims beyond the source-code evidence and the passive English HTTP check.

## 3. Financial semantics

The current implementation treats a Loan as a **scheduled obligation**, not a bank account and not a cash balance. Creation stores the obligation, calculates its schedule, and explicitly tells the user that borrowed cash is not added to an account. The only current money movement is a scheduled payment from a selected liquid source account. The payment RPC returns the ledger transaction, payment record, principal/interest split, source delta, remaining principal, and completion metadata. [1] [2]

## 4. Conditional states

| Condition                               | Actual UI branch                                                                                                                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Active loan                             | Appears in Active loans. A mutable owner can see payment, payoff estimate, and History & actions.                                                                                                                              |
| Completed loan                          | Appears in the non-active history group. Detail omits payment actions, shows completion copy, and offers Open Inbox. Completion is produced by a scheduled payment response or inferred when remaining principal reaches zero. |
| Cancelled/defaulted loan                | Appears in the non-active history group and detail status fallback. No payment/edit/archive actions are rendered.                                                                                                              |
| Archived loan                           | Appears in history and is reference-only. The current active UI has no unarchive or delete control.                                                                                                                            |
| No remaining principal                  | Mapper clamps remaining principal to zero and converts Active to Completed; progress reaches 100%.                                                                                                                             |
| Partially paid / partial schedule entry | Partial schedule rows are included in the next-payment candidates. A payment action remains possible when the row is upcoming/partial, the loan is active, and the viewer can mutate.                                          |
| No upcoming payment                     | Pay action is replaced with “No upcoming schedule entry to pay.”                                                                                                                                                               |
| No next payment date                    | List shows “No next payment”; detail due state is `none`.                                                                                                                                                                      |
| Upcoming                                | More than 7 days until due; neutral informational date copy.                                                                                                                                                                   |
| Due soon                                | 1–7 days until due; detail uses info styling and list includes due-soon copy.                                                                                                                                                  |
| Due today                               | Same calendar date; detail uses warning styling.                                                                                                                                                                               |
| Overdue                                 | Due date is in the past; list/detail use danger styling.                                                                                                                                                                       |
| Interest-free                           | Annual rate is present and equal to zero; list displays Interest-free.                                                                                                                                                         |
| Fixed interest                          | One annual rate field; future-rate action is hidden and the server rejects rate updates.                                                                                                                                       |
| Floating interest                       | Current interest field; future-rate action is available only when other server conditions pass.                                                                                                                                |
| Promotional fixed-to-floating           | Additional fixed rate, fixed months, floating rate, and optional effective-date fields; preview shows a post-change payment; future-rate editing is hidden before the promo switch.                                            |
| Fixed monthly repayment                 | Annuity-style monthly payment; simulation and schedule provide a stable first/monthly payment.                                                                                                                                 |
| Reducing-balance repayment              | Equal principal slices with declining interest and varying total payment; the UI still labels the primary amount as monthly payment.                                                                                           |
| Owner/mutable                           | `ownership.canMutate` and Active status permit action controls.                                                                                                                                                                |
| Partner/former-member/read-only         | Ownership badge and explanation remain visible; edit, payment, interest-update, and archive triggers are omitted rather than merely disabled.                                                                                  |
| Payment source required                 | Payment form requires one of the passed liquid non-credit-card accounts. No eligible account disables the preview action.                                                                                                      |
| Account read failure                    | The Loans detail page receives the account read result, but the current payment UI has no separate account-load error branch; an empty/missing account is handled as invalid/disabled.                                         |
| Scheduled payment success               | Receipt shows the principal/interest split, source, remaining principal, linked transaction(s), and recorded/completed outcome.                                                                                                |
| Idempotent replay                       | Receipt uses replay copy and states that no additional payment was made.                                                                                                                                                       |
| Schedule read failure                   | Overview can remain visible while the schedule tab shows a separate ErrorState; full schedule also has its own ErrorState.                                                                                                     |
| Payment-history read failure            | History tab shows a separate ErrorState while other detail content remains available.                                                                                                                                          |
| Rate-history read failure               | History tab shows a separate ErrorState and retry link.                                                                                                                                                                        |
| Empty loan list                         | Whole-page EmptyState with Add loan still available.                                                                                                                                                                           |
| Empty payment history                   | “No payments recorded yet.”                                                                                                                                                                                                    |
| Empty rate history                      | “No rate changes recorded yet.”                                                                                                                                                                                                |
| Empty schedule                          | “No schedule entries yet”; full schedule has no year selector.                                                                                                                                                                 |
| Offline                                 | Review remains visible, but mutation triggers and saves are disabled or return the offline error.                                                                                                                              |
| Invalid detail ID                       | Detail uses Loan not found EmptyState with Back; the nested schedule route uses ErrorState for the same read result.                                                                                                           |

- [ ] Cover name, household/personal financial scope, optional lender, loan type, and positive integer principal.
