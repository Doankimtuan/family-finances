# Family Finance — Debt UI Surface Inventory

**Scope:** Discovery only. No Debt UI, business logic, route, database, i18n, or styling changes were made.

**Repository inspected:** `family-finances`

**Primary implementation root:** `app/[locale]/(product)/money/debts/`

## Executive summary

The current Debt experience is a compact Money child flow with one list page, one detail page, three action sheets, one embedded payment-history section, and route-level loading/error/not-found states. There is no separate payment-history page, repayment-schedule page, source-account page, destination-account page, archive/delete dialog, mark-paid action, overflow menu, query-param-driven modal, or Debt-specific nested route beyond the detail route.

The canonical active flow is:

> **Money hub → Debt list → Create Debt sheet → optional money-movement review → receipt → Debt detail → Edit details sheet or Repay/Receive sheet → review → receipt → linked transaction; detail also exposes embedded payment history and links to transaction detail.**

The most important redesign coverage issue is that the Debt detail currently uses colored `text-debt` / `text-income` styling for current remaining amounts, while the design system specifies neutral treatment for current-state balances and reserves semantic color for movement or attention. The not-found detail state also uses an `EmptyState` where the canonical detail guidance calls for a danger `StatusAlert` plus a back link. Archived data is modeled and displayed in history, but there is no current user-facing archive/delete mutation surface.

## 3. Conditional states

### Lifecycle and progress

| Condition      | Actual implementation behavior                                                                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Active debt    | Included in active list and summary; mutable owner sees Edit and payment action; due state is derived.                                                                                              |
| Completed debt | Excluded from active totals; shown in history; detail shows “This record is complete.” instead of payment action; due badge becomes Completed; history empty copy uses completed copy.              |
| Archived debt  | `DebtStatus.ARCHIVED` is modeled and included in non-active history; edit is suppressed by `!debt.isArchived`; payment is suppressed because status is not Active; no archive/delete UI is present. |
| No payment yet | Progress state is `NOT_STARTED`, percentage 0, and payment history can show its directional empty message.                                                                                          |
| Partially paid | Progress state is `IN_PROGRESS`; paid/received amount and percentage render; remaining amount remains positive and payment CTA remains available when mutable/active.                               |
| Fully paid     | Remaining amount is 0; progress is 100 and `COMPLETED`; payment CTA is absent and completion text/badge appears.                                                                                    |

### Due-date states

`getDebtDueInfo` derives the following visible states. Due state is hidden for active debts with no due date.

| Derived state | Condition                          | Visible treatment                                                    |
| ------------- | ---------------------------------- | -------------------------------------------------------------------- |
| None          | Active and no due date             | No `DebtDueBadge`.                                                   |
| Upcoming      | Due date more than 7 days away     | Informational badge with absolute due date.                          |
| Due soon      | Due date within 7 days, not today  | Warning badge with days left.                                        |
| Due today     | Due date equals today              | Warning badge “Due today”.                                           |
| Overdue       | Due date before today              | Attention badge with days overdue; summary overdue count increments. |
| Completed     | Non-active or remaining amount ≤ 0 | Positive/completed badge.                                            |

The list summary increments `dueSoonCount` for Due soon and Due today, and `overdueCount` for Overdue. There is no due-date action, reminder sheet, or schedule view.

### Direction and recording mode

| Condition                  | Actual branch                                                                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Borrowed                   | “To repay”, “Still to repay”, “Repay debt”, source account “Pay from account”, repayment labels, debit-like history amount, and borrowed meaning copy.                      |
| Lent                       | “Waiting to receive”, “Still to receive”, “Receive payment”, destination account “Receive into account”, receipt labels, credit-like history amount, and lent meaning copy. |
| Existing balance           | No account picker; saves the tracked debt without current account movement.                                                                                                 |
| Money moves now            | Account picker is required; review state and receipt include account movement and linked transaction.                                                                       |
| Due date present           | Due date appears in form, detail facts, and derived badge.                                                                                                                  |
| Due date absent            | Due-date field remains optional; detail facts omit it and no due badge appears while active.                                                                                |
| Due date before start date | Create/edit schema rejects it; field-level invalid state is shown through shared form error rendering.                                                                      |

### Ownership and membership

| Condition                       | Actual branch                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Household scope                 | Both household members can manage; `canMutate` is true.                                                                    |
| Personal, current user owns it  | `Personal · You`; `canMutate` is true while owner membership is active.                                                    |
| Personal, partner owns it       | `Personal · Partner`; `canMutate` is false; edit/payment triggers are omitted; ownership explanation is shown.             |
| Personal, former member owns it | `Personal · Former member`; `canMutate` is false; a former-member explanation is shown; edit/payment triggers are omitted. |
| Unauthenticated                 | Debt list/detail guards redirect to English login when accessed as `/en/...`.                                              |
| No active household membership  | Debt list/detail guards redirect to onboarding.                                                                            |

### Data and failure states

| Condition                           | Actual branch                                                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Debt list read fails                | Page renders `StatusAlert` with retry; create sheet remains available in the error branch.                                                       |
| Debt detail read fails              | Page renders danger `StatusAlert`, retry same detail route, and Back to debts.                                                                   |
| Debt detail not found               | Page renders `EmptyState` and Back to debts.                                                                                                     |
| Payment-history read fails          | Detail remains available; history section shows independent danger alert and retry.                                                              |
| Payment history empty               | Direction-specific empty message; completed debt uses completed copy.                                                                            |
| Payment history populated           | Count and total tracked render; each recorded payment links to its transaction.                                                                  |
| Opening amount paid before tracking | Synthetic non-clickable history row is rendered and included in count/total.                                                                     |
| History does not reconcile          | Danger reconciliation warning appears above the history rows.                                                                                    |
| Account list read fails             | Create/payment sheet shows danger account-load alert and Retry.                                                                                  |
| No eligible liquid accounts         | Create/payment sheet shows warning alert; primary action is disabled.                                                                            |
| Offline                             | List/detail show read-only banner; mutation triggers and submit actions are disabled; attempted review/submit paths can show offline error copy. |
| Invalid amount/account/date         | Shared form validation surfaces generic localized invalid copy; payment amount cannot exceed remaining principal.                                |
| Mutation error                      | Action sheet remains open and renders a danger `StatusAlert`; successful mutation produces a receipt and refresh.                                |
| Idempotent replay                   | Create/payment receipt uses distinct replay copy and states that no duplicate movement/payment was created.                                      |

## 6. Legacy / inconsistent UI

The following are the highest-priority inconsistencies for a future redesign. They are observations only; nothing was changed.

| Surface                          | Finding                                                                                                                                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Debt detail status/amount card   | Current remaining principal is rendered with `text-debt` for borrowed and `text-income` for lent. The design system specifies neutral text for current-state values and reserves positive/negative tones for movements.                           |
| Debt list current amounts        | Active row and overview amounts also use domain semantic colors for static remaining balances. This is inconsistent with the current-state financial semantics in the canonical design reference.                                                 |
| Detail not-found                 | Code uses `EmptyState` plus a link. The canonical detail guidance calls for a danger `StatusAlert` plus a back link for detail-not-found. Existing screenshot evidence shows the compact empty state treatment.                                   |
| Detail action fallback           | For non-active/non-mutable records, the detail renders a second `FinancialOwnershipBadge` in the action area even though ownership is already rendered in the facts section. This can duplicate context for archived/completed/read-only records. |
| Loading skeleton implementations | List and detail loading use a mixture of shared `Skeleton` and custom pulse blocks. The detail skeleton is not clearly composed from the exact loaded hierarchy and should be rechecked during redesign.                                          |
| Local hand-styled links          | Retry, back, transaction, and some action links use local class strings instead of shared button/link primitives. This is a consistency concern rather than a functional gap.                                                                     |
| Long create/payment sheets       | The current sheets contain many sequential sections and conditional branches. The structure is functional but should be audited for scanability and mobile keyboard/scroll behavior.                                                              |
