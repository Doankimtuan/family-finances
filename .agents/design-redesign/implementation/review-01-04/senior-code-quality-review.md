# Senior code quality review — Implementations 01–04

## Scope and evidence

Reviewed the changes from `origin/main...HEAD` (Foundations, Core Reusable Components, Overlays/Feedback/Forms, and Navigation/Shell), their product callers, the existing `shared/patterns` and form controls, unit tests, and the current working tree on 2026-09-27. Implementation 04's commit changes documentation only; the existing shell was reviewed as context, not attributed to that implementation. This is a code-quality review, not a UI redesign. No production code was changed for this review.

The requested `review-01-04/` hardening artifact was absent before this review. The prior in-chat hardening review identified seven issues. All seven remain in the inspected code; none is marked fixed. Its earlier report of passing focused tests, lint, typecheck, and build is historical evidence, not a substitute for browser evidence or the checks on this review's current tree. Concurrent uncommitted edits to checkbox, radio, their demo, and tests were read as current code and left untouched.

## Design pattern assessment

| Pattern                          | Classification   | Assessment                                                                                                                                |
| -------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Compound components              | APPROPRIATE      | HeroUI-backed `ActionMenu` and form item composition are familiar; CQ-09 is a styling/API defect, not an argument to replace the pattern. |
| Composition                      | APPROPRIATE      | `DateInput` over `DatePickerField` and small field wrappers are useful when they add a real affordance.                                   |
| Provider / Context               | APPROPRIATE      | Theme and radio group state have shared descendants; CQ-02 and CQ-13 fix their contracts without adding providers.                        |
| Adapter                          | NEEDS REFACTOR   | The existing HeroUI adapters are useful, while the new overlay adapters duplicate the existing pattern surfaces (CQ-01).                  |
| Facade                           | OVERENGINEERED   | Parallel dialogs/sheets/toasts and copied numeric fields add a second facade without a distinct recurring need (CQ-01, CQ-10).            |
| Strategy                         | MISAPPLIED       | Action menu accepts a broader variant strategy than it implements (CQ-09).                                                                |
| Configuration-driven UI          | MISAPPLIED       | Domain-specific empty-state variants and percentage policy are embedded in generic primitives (CQ-11).                                    |
| Controlled / uncontrolled        | NEEDS REFACTOR   | Checkbox and RadioGroup expose uncontrolled options but do not faithfully render them (CQ-02, CQ-03).                                     |
| Render props / slots             | APPROPRIATE      | HeroUI slots are used for real component structure. No new render-prop framework is warranted.                                            |
| Custom hooks                     | APPROPRIATE      | `useTheme` exposes a real shared external store; repair its fallback rather than replace it.                                              |
| Utility abstraction              | UNDER-ABSTRACTED | The quick-chip regex should use existing/standard locale formatting (CQ-14); duplicated token constants over-abstract static CSS (CQ-16). |
| Variant systems                  | NEEDS REFACTOR   | Existing button aliases have product callers; action-menu coverage and CSS token references need alignment (CQ-09).                       |
| State machines                   | APPROPRIATE      | None introduced in this diff; there is no flow complex enough here to justify adding one.                                                 |
| Repository / service abstraction | APPROPRIATE      | Not changed by these UI implementations; do not introduce a new one for presentation work.                                                |

## Ponytail deletion opportunities

- `shared/ui/bottom-sheet.tsx`, `dialog.tsx`, `toast.tsx`, and corresponding `shared/patterns/*`: one HeroUI implementation plus compatibility exports avoids repeated surface/slot code.
- `shared/ui/form/currency-input.tsx`, `number-input.tsx`, `percentage-input.tsx`, `quantity-input.tsx`: reuse existing money/number field behavior; keep only the affordances the product actually calls.
- `shared/theme/tokens.ts` JavaScript dimension mirrors and unused `--vn-*` CSS aliases: remove only after consumer verification; static CSS needs one source of truth.
- `CurrencyInput` compact-number regex: one locale formatter call is simpler and correct across supported locales.

`net: -300 lines possible.` This is a directional estimate after compatible migration, not a measured patch size.

## Test and browser evidence

Existing component tests demonstrate basic rendering and clicks but omit default values, disabled options, mixed accessibility, keyboard tabs, locale copy, and target sizes. Foundation tests assert copied numeric constants rather than the rendered controls. The prior hardening turn reported 50 focused tests and lint/typecheck/build passing. No real-browser QA was independently completed for this review; the UI should not be declared verified at 390, 440, 768, or 1280px from these tests alone. Each behavior fix in the plan includes a focused check and the UI acceptance pass required by the project instructions.

## Do not change

1. Preserve the intentional centered 440px shell, single scroll owner, server-side route/auth layout, and portal containment. Implementation 04 is documentation-only and provides no evidence for a shell rewrite.
2. Preserve HeroUI v3, `shared/ui`/`shared/patterns` conventions, and existing product-facing compatibility imports during consolidation. Do not add another UI system, generic form engine, or provider layer.
3. Preserve the existing numeric domain value contract and application-layer financial semantics. Reuse `MoneyInput`/`AmountField`/`NumberField` behavior rather than inventing persisted formatted strings.
4. Keep `useSyncExternalStore` for theme hydration and system changes; correct the failed-storage branch only.
5. Keep button alias variants with real product callers until a deliberate migration. Tree shaking or bundle harm from the barrel exports was not measured, so no barrel rewrite is recommended.
