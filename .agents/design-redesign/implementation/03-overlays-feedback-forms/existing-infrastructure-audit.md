## 1. Executive Summary

This audit inspects the current codebase for existing implementations, abstractions, and primitives corresponding to the 14 overlay, feedback, loading/empty/error, and form infrastructure components specified in Task 11.

Each element is classified into one of the canonical categories:

- **REUSE**: The existing implementation or underlying HeroUI/React Aria primitive is fully accessible and fits the canonical specifications; consume or adapt it directly.
- **RESTYLE**: The structural logic is sound, but colors, borders, shadows, or typography need alignment with canonical tokens.
- **REFACTOR**: The component exists but needs structural improvements (e.g. splitting slots, exposing canonical variants, unifying focus/keyboard behavior).
- **REPLACE**: The existing component is obsolete or non-compliant and must be superseded by a canonical primitive.
- **DEPRECATE LATER**: The legacy pattern should be preserved as an alias or compatibility wrapper during Implementation 03, then phased out when domain screens are migrated.
- **UNKNOWN**: No precedent found in current codebase; new canonical primitive created from scratch.

## 4. Architectural Rules for Phase 3–18

1. **Accessibility First**: Use HeroUI (`Modal`, `Drawer`, `Dropdown`, `Toast`) to guarantee focus trapping, Escape key listener, ARIA roles (`alertdialog`, `menu`, `alert`, `status`), and screen-reader announcements.
2. **Design Tokens Only**: All borders use `--border-subtle` / `--border-default`, radiuses use `--radius-overlay` (16px), `--radius-control` (10px), `--radius-card` (12px), and z-indexes use `--z-scrim` (50), `--z-modal-sheet` (60), and `--z-toast` (70).
3. **No Domain Code Migration**: Keep this implementation strictly in `shared/ui/` and `shared/ui/form/`. Do not touch product domain screens.
