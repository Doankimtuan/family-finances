# Loans 11C — List + Create UX

## Verdict

# LOANS LIST/CREATE READY

Scope was limited to the Loans list/overview and create flow. No detail/payment UI or production fee persistence was added. The 11B idempotency contract remains unchanged.

## Implemented

### List

- Active loans and completed/cancelled/defaulted/archived history render in separate sections.
- The list read model now includes the next upcoming schedule total.
- Due state is derived from the household date: upcoming, due soon (within seven days), due today, overdue, or no next payment.
- Reducing-balance loans use “First payment” rather than implying a fixed monthly amount.
- Tracking-only copy states that borrowed cash is not automatically added to an account.
- Existing archive/status model remains the only history action; no hard delete was added.

### Privacy and state handling

- Loan remaining, first/monthly payment, next payment, and create-preview amounts are rendered through `FinancialValue`.
- Existing privacy provider toggle was exercised authenticated with values hidden and revealed.
- Added a Loan-specific loading skeleton route.
- Empty state remains distinct from `listLoans() === null` read failure.
- Read failure has a localized Retry link.
- Existing `MoneyOfflineBanner` remains visible; create is disabled offline, leaving the list read-only.

### Create flow

- Existing amortization inputs, preview math, validation schema, and 11B idempotency key are preserved.
- Create is now required-first progressive: basics, then terms/schedule details.
- Continue validates the first step at field level before advancing.
- Save, Back, and Cancel use the shared sticky `BottomActionBar` with 44px targets.
- Defaults are generated by `getDefaultValues()` on open/reset, so the start date is not captured at module load.
- Reopening after cancel or success starts from fresh defaults.
- Preview amounts use `FinancialValue` and retain existing schedule calculations.

## Invariants and regressions

The 11B financial integrity contract remains covered and passing:

- borrowed principal is not Income;
- principal repayment is not Expense;
- interest remains Expense;
- account debit remains principal plus interest;
- loan remaining decreases by principal only;
- create/payment retries remain idempotent;
- Home metrics and raw Transactions semantics are unchanged;
- no hard delete was introduced.

Added 11C due-state unit coverage for null, overdue, today, due-soon, and upcoming dates.
