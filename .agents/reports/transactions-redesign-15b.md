# Transactions redesign — implementation and verification report

## Status

**Implemented and verified for the active Transactions UI surfaces.** The redesign remains discovery-led, compact, and management-oriented. Existing transaction semantics, route contracts, ownership gates, balance effects, Home cash-flow inclusion/exclusion, Supabase/RPC behavior, i18n namespaces, shared financial formatters, and ledger query behavior were preserved.

The visual direction is a calm ledger scanner: restrained surfaces, compact date rails, a light date-spine treatment, stable right-aligned tabular amounts, selective deep-teal emphasis, and semantic tones that do not rely on color alone. Motion is limited to the existing `motion/react` system’s conditional form transition; no new drag/gesture or decorative animation was added.

## Semantic safety checks

The redesign did not modify `financial-semantics.ts`, `income-exclusion-policy.ts`, transaction command schemas/actions, Supabase/RPC/migrations, ownership rules, route helpers, or ledger query semantics.

The following behavior remains unchanged: ordinary income and expense count toward Home cash flow; internal transfers, refunds/reversal legs, reversed originals, principal movements, borrowing, debt movements, liability payments, investment buy/sell proceeds, and savings principal remain excluded from ordinary monthly income/expense; investment income, investment fees, loan interest, savings interest, and savings tax/fee retain their current semantic inclusion; transfer legs and loan-payment legs remain grouped as user-facing activities; correction remains a linked chain; refund remains a reversal relationship; and generic Correct/Refund actions remain capability- and status-gated.
