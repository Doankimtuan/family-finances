# Deferred Features

Deferred capabilities are valid but should wait until future releases.

| Capability | Why Deferred | Future Trigger |
|---|---|---|
| Joint ownership | Legal nuance is real but too heavy for MVP. | More shared-account or dispute use cases. |
| Currency eligibility | Most target MVP behavior can assume VND. | Multi-currency deposits or expatriate users. |
| Min/max amount | Useful for provider packages, not household core. | Larger provider catalog. |
| Provider status | Infrastructure value, low daily user value. | Live provider feeds or package changes. |
| Provider concentration | Important as balances grow. | Households hold larger savings across banks. |
| Deposit insurance exposure | Correct but advanced. | Savings balances exceed insured threshold. |
| Tax treatment | Current individual bank-deposit interest is generally not taxable; rules may change. | Multi-jurisdiction, business, or investment-like products. |
| Changed term lengths | Rare compared with rate/package changes. | Provider package migrations. |
| Mark provider inactive | Operational capability. | Provider catalog becomes dynamic. |
| Eligibility/residency restrictions | Important but edge-heavy. | Foreign users or foreign-currency products. |
| Pledged/collateral status | Real but uncommon for young household MVP. | Mortgage collateral or bank-secured loans. |
| Power of attorney/inheritance/freeze | Critical edge cases, not everyday. | Family/elder support expansion. |
| Provider unavailable warning | Depends on provider data quality. | Reliable provider/package source exists. |
| Liquidity ladder | Valuable once multiple maturities exist. | Multi-product households. |
| Insured versus uninsured exposure | Advanced safety insight. | Larger balances/provider concentration. |
| Audit provider statement evidence | Trust-critical but operationally heavy. | Bank feed/import or mature reconciliation. |

Deferred does not mean unimportant. It means the capability should not burden the first durable Savings experience.
